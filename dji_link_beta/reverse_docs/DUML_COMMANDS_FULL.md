# DJI DUML Command Payload Reference — Mavic Mini 1 (WM160) / DJI Fly v1.21.4

**Master byte-layout reference for every DUML command that the DJI Fly app has a request/response builder for.**
Generated by disassembling the app's protocol classes and reading each builder directly — no invented layouts.

---

## Methodology & evidence base

Every **builder-verified** entry below is extracted from the app's own packing code:

- **Payload layout** ← the class's `doPack()V` method (builds the `_sendData` byte array).
- **cmd_set / cmd_id / receiver** ← the class's `start(...)` method (fills `Pack.m`=cmd_set, `Pack.n`=cmd_id, `Pack.f`=sender, `Pack.h`=receiver).
- Classes live in `uav/midware/data/model/P3/Data*` inside `unpacked_app_dex/classes_0451d00c.dex`; enums in `.../config/P3/` inside `classes_016b200c.dex`.
- Enum → number resolution is programmatic: `CmdSet`, `CmdId<Set>$CmdIdType`, and `DeviceType` all store their numeric value as the 3rd constructor arg. (e.g. `CmdIdFlyc.s`→0x2D, `DeviceType.FLYC`→3.)

**To (re)verify any single command by hand:** disassemble the DEX and read the named class:
```
baksmali d unpacked_app_dex/classes_0451d00c.dex -o p3smali
less p3smali/uav/midware/data/model/P3/<DataClass>.smali   # read doPack() + start()
```

### BytesUtil encoders (how `doPack` serialises each field)
| helper | meaning | width |
|---|---|---|
| `u(I)` | int→byte | 1B |
| `D(S)` | int16 little-endian | 2B |
| `n0(I)` | uint16 little-endian | 2B |
| `z(I)` | int32 little-endian | 4B |
| `o0(J)` | uint32 LE (low 32 of long) | 4B |
| `y(F)` | float32 LE (`floatToIntBits`→z) | 4B |
| `A(J)` | int64 LE | 8B |
| `x(D)` | float64/double LE (`doubleToLongBits`→A) | 8B |
| `f([B[BI)` | append src bytes into dest at offset | — |
| `x0(IIB)` | set/clear one bit in an int (bitfield) | — |

All multi-byte scalars are **little-endian**. `flags/computed byte` = a bitfield assembled with shifts/ORs; the exact bit meaning is in that class's `doPack()` (byte-level, not a single field).

### Confidence levels
- **builder-verified** — layout, cmd_set, cmd_id and receiver all read from the app class named in the row.
- **name-only** — command exists in the DUML map (`full_table.txt` / firmware naming) but the app ships no packing class here, so no byte layout is asserted.

### Receiver (DeviceType) codes
`WHO=0 CAMERA=1 APP=2 FLYC=3 GIMBAL=4 CENTER=5 RC=6 WIFI=7 DM368=8 OFDM/OSD=9/0xe SINGLE(vision)=0x11 DOUBLE=0x12 BATTERY=0xb GPS=0x1a GLASS=0x1c`  
(Sender is always APP=0x02 / PC=0x0a for these app-originated commands.)

> Note: for a few command sets the app's class-name prefix differs from the firmware set label — noted per section. The **numeric cmd_set matches** the firmware in all cases.
